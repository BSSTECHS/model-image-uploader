# 型号图片批量上传

飞书多维表格边栏插件：读取当前数据表的字段和记录，按本地型号文件夹名匹配记录，把图片批量写入指定附件字段。

## 你要怎么用

### 方式一：本机立即调试

1. 安装 Node.js 20.19+ 或 22.12+。
2. 在完整源码项目目录执行：

   ```bash
   npm install
   npm run dev
   ```

3. 保持终端运行，打开目标多维表格。
4. 点击右上角「多维表格插件」图标，再点击底部「自定义插件」。
5. 点击「+ 新增插件」，填写：
   - 插件名称：`型号图片批量上传`
   - 服务地址：`http://localhost:3000/`
6. 确定后打开插件，顶部应显示当前数据表名称。
7. 在两个下拉框中分别选择：
   - 匹配字段：`modelNum`
   - 上传字段：`上架图片`
8. 选择目录，核对每个型号的匹配预览，先用测试记录和默认“追加”模式上传。

`localhost` 只在运行项目的这台电脑有效。关闭终端或电脑后插件无法打开，同事也不能使用这个地址。

### 方式二：部署后长期使用

1. 对完整源码执行 `npm run build`，或直接使用交付的部署包。
2. 把部署包中的 `index.html`、`assets/`、图标、清单等全部上传到同一静态网站目录。
3. 得到一个可访问的 HTTPS 地址，例如 `https://your-domain.example/model-image-uploader/`。
4. 静态服务不得通过 `X-Frame-Options: DENY` 或限制性 CSP `frame-ancestors` 禁止飞书嵌入。
5. 每位使用者在多维表格中进入「插件 → 自定义插件 → + 新增插件」，填写同一个部署地址。
6. 添加后即可在边栏中读取当前数据表并使用。

这只是静态页面托管，不需要 Node 后端、数据库、`Personal Base Token` 或 App Secret。资源使用相对路径，可放在域名根目录或子目录。

## 目录选择方式

### 总文件夹（批量，默认）

一次选择总文件夹，按一级子文件夹名拆分型号：

```text
商品图片/
├── A001/
│   ├── 主图.jpg
│   └── 细节/
│       └── 细节1.jpg
├── A002/
│   └── 主图.png
└── SPACE 001/
    └── 主图.webp
```

插件会生成 `A001`、`A002`、`SPACE 001` 三个任务，分别匹配字段值完全相同的记录。型号目录内更深层子目录的图片也会包含。

可继续点击“继续添加总文件夹”添加另一批；同型号任务会合并，同一路径、大小和修改时间的文件会去重。浏览器目录弹窗通常一次只能选一个目录，因此批量操作推荐选择总文件夹。

总文件夹根目录直接散放的图片无法判断型号，会显示为“根目录散图”并阻止上传，不会误写记录。

### 单个型号文件夹

选择“单个型号文件夹”后：

```text
A001/
├── 主图.jpg
└── 细节/
    └── 细节1.jpg
```

所选文件夹名 `A001` 就是型号，内部所有层级的图片都会上传到 `modelNum=A001` 的记录。

已有任务时目录方式会锁定，点击“清空”后可切换。

## 字段与匹配规则

- 插件通过飞书 JS SDK 读取当前活动数据表，不是读取演示数据。
- 匹配字段下拉框列出当前表的文本和数字字段，默认优先选择 `modelNum`。
- 上传字段下拉框列出当前表的附件字段，默认优先选择“上架图片”。
- 切换任一字段后自动重新读取并匹配，也可点击“刷新匹配”。
- 文件夹名与匹配字段的整个值精确匹配，不拆分空格或标点，不做模糊匹配。
- 匹配前只做文件名必要的规范化：Unicode NFC、去首尾空格、Windows 禁止字符替换为 `_`。
- 同一型号对应多条记录、未匹配、无图片、超过附件上限都会阻止对应任务并说明原因。

## 上传安全规则

- 默认保留原附件并追加；主动勾选“覆盖已有附件”后才会替换原附件。
- 单个附件单元格最多 100 个附件，匹配时预检，写入前再次复核。
- 每个型号独立上传，单个失败不中断后续型号，失败项可单独重试。
- 上传开始后锁定字段、目录和覆盖设置。
- 读取与写入固定到插件启动时的数据表，避免切换活动表后写错表。
- 图片只从当前浏览器传给飞书，不经过第三方服务。

## 真实表联调清单

已验证目录读取、总目录批量拆分、多级目录图片、重复添加去重、字段下拉切换、匹配状态、附件上限及窄屏布局。飞书真实附件上传与写回仍需在公司多维表格内联调，因为开发环境没有公司表的登录与写入权限。

首次联调：

1. 复制目标表，或新建 `TEST001`、`TEST002` 两条专用测试记录。
2. 准备同名型号文件夹，先以追加模式上传 `TEST001`。
3. 检查“上架图片”中的文件名、数量和顺序，再追加一张确认原附件保留。
4. 用 `TEST002` 测试覆盖模式，确认只影响该测试记录。
5. 检查重复型号、未匹配、根目录散图、无图片及超过 100 个附件的拦截。
6. 模拟断网或权限不足，确认失败原因和重试行为。
7. 联调通过后再用于正式数据。

## 使用限制

- 匹配字段当前支持文本和数字；公式、查找引用等字段类型未纳入下拉框。
- 浏览器不会返回完全空白文件夹中的任何条目；只有非图片文件的文件夹会显示“无图片”。
- 上传期间不要关闭插件或刷新页面；写回成功的型号会标记为“已完成”。
- 覆盖操作会替换目标单元格原附件，正式数据使用前务必备份并完成追加模式联调。
